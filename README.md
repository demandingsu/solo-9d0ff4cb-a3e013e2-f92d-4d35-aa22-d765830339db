# 隔声试验数据交付复核工具

声学实验室向外部复核方交付隔声试验数据的网页工具：从上传的 SQLite 库中勾选试验、
剔除个别异常读数，沿对照/校准引用自动补齐所需记录，确认预览后下载 SQLite 子库。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements-dev.txt
python3 scripts/make_sample_db.py sample.db   # 生成演示库
uvicorn app.main:app --reload
```

运行测试：`pytest`

## 共测链比对（多实验室复测）

多家实验室用部分相同的隔声试件复测时，用 `/compare` 页面登记共测关系并检查
“某试件出问题时，哪些实验室之间没法比对”。

### 数据约定

- 实验室沿用源库 `groups` 表：一个组视作一家实验室（组名即实验室名）；
- 每条共测记录填写：试件号、两家实验室（组 id）、两家实验室在该试件上
  各自的同频读数编号；两条读数的 `frequency_hz` 必须相同，否则拒绝登记；
- 同频读数从读数自身列读取，不需要额外的频点表；
- 共测记录与复核状态保存在会话目录的旁路库 `cotest.db` 中，**不改写上传的源库**；
  撤回为软删除（保留历史，页面“已撤回记录”可查）。

### 结论口径

选一家实验室作参照后，逐频点分析（每个频点独立计算连通性）：

1. **可比实验室**：以参照为起点，沿该频点的有效共测记录做广度优先遍历，
   能到达的实验室即可与参照经共测链比对；页面给出实际走过的链（含试件号与读数）；
2. **关键试件**：对每个试件，临时撤掉它在当前频点的**全部**共测记录后重新遍历，
   若某个原本可比的实验室因此不可达，该试件即关键试件，并列出会断链的实验室；
3. **结论指纹**：由“参照实验室 + 频点 + 该频点全部有效记录（试件号与两家实验室）+
   可比实验室集合 + 关键试件及其断链实验室”计算。负责人确认的是某一频点的这份指纹；
   纳入记录集合意味着该频点任一登记/撤回都会让旧页面令牌失效，
   但其他频点的结论不受影响。

### 复核状态

- 负责人点“确认所见结论”，记录该频点当前指纹；
- 任何登记/撤回后都会在同一事务中重算所有已确认频点的指纹：
  指纹变化的确认被删除（回到待复核），其余确认保留；
- 确认表单携带页面生成时的指纹；若页面打开后该频点的记录、连通性或关键试件清单
  已变化，提交会被拒绝（HTTP 409）且不写入确认——旧页面不能确认已变动的结论；
- 登记/撤回与复核状态刷新在同一 `BEGIN IMMEDIATE` 事务中提交，任一步失败整体回滚，
  原记录与复核状态保持不变。

### 演示样例（同一试件支撑多段共测链）

用 `scripts/make_sample_db.py` 生成的演示库上传后，共测记录页在无记录时提供
“载入演示共测记录”，写入：

| 试件 | 频点 | 记录 |
| --- | --- | --- |
| S-墙体-01 | 100 Hz | A(#101)—B(#201) |
| S-墙体-01 | 100 Hz | B(#201)—C(#901) |
| S-墙体-02 | 100 Hz | A(#101)—C(#901)（冗余直连） |
| S-墙体-01 | 125 Hz | A(#102)—B(#202) |
| S-墙体-01 | 125 Hz | B(#202)—C(#902) |

试件 S-墙体-01 在 100 Hz 与 125 Hz 都同时支撑 A—B、B—C 两段链：

- 100 Hz：撤掉 S-墙体-01 后 B 断链，C 仍可经 S-墙体-02 直连；
- 125 Hz：撤掉 S-墙体-01 后 B、C 同时断链。

## 数据库结构约定

上传的 SQLite 库需包含四张表（关键列名固定，其余列任意）：

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `groups` | `id`, `name` | 试验组 |
| `calibrations` | `id`, `device` | 校准记录 |
| `tests` | `id`, `group_id→groups`, `calibration_id→calibrations`(可空), `name` | 试验 |
| `readings` | `id`, `test_id→tests`, `calibration_id→calibrations`(可空), `control_reading_id→readings`(可空), `kind` | 读数；`control_reading_id` 为对照读数引用，允许跨组 |

## 交付规则

1. 交付所选试验中未被剔除的全部读数；
2. 沿对照引用（`control_reading_id`）与校准引用（`calibration_id`，读数级与试验级）
   补齐所需记录；对照读数允许跨组互引；
3. 跨到未勾选的组时，只带入沿引用找到的读数，以及这些读数所属的试验、
   试验所属的组（维持外键完整所必需）和引用到的校准记录；
4. 引用悬空（目标不存在）或指向已剔除读数时，预览页展示完整引用链并**阻止下载**；
5. 子库建表语句复用源库 DDL 原文，主键、外键约束、索引原样保留，行按原主键写入，
   导出后执行 `PRAGMA foreign_key_check` 校验。

## 使用流程

1. **上传**：选择实验室导出的 SQLite 库（结构不符会给出具体缺失项）；
2. **共测链比对**（可选）：在 `/compare` 登记共测记录、逐频点查看可比实验室与
   关键试件，负责人确认结论（详见上一节）；
3. **选择**：按组勾选要交付的试验，可在所选试验下勾选要剔除的异常读数；
4. **预览**：查看交付汇总、跨组带入的读数及其引用链；若存在引用冲突，
   展示每条冲突的完整引用链，下载按钮禁用；
5. **下载**：确认后下载 `*_subset.db`。下载前服务端会重新解析一次，
   若状态已变化产生冲突则返回 409 拒绝。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATA_DIR` | `./data`（容器内 `/data`） | 上传文件与子库的工作目录 |
| `MAX_UPLOAD_MB` | `200` | 上传大小上限 |

## 已知限制

- 会话以 cookie 标识，工作目录（源库 + `cotest.db`）保留在 `DATA_DIR`；
  进程重启后凭原 cookie 自动恢复；需运维定期清理 `DATA_DIR`（未实现自动清理）；
- 共测链页面单会话写操作用进程内锁串行化，跨进程一致性依赖 SQLite
  `BEGIN IMMEDIATE`；未做多用户隔离与鉴权，仅供实验室内网使用；
- 实验室与组按 1:1 处理（一个 `groups` 行视作一家实验室）；同一实验室若在库中
  拆成多组，需在上传前合并或另行约定；
- 关键试件分析为“单个试件全撤”的一阶分析，不枚举多个试件同时撤回的组合；
- 表名/关键列名固定，如实验室库结构不同需先适配（见 `app/core.py` 顶部约定）。
